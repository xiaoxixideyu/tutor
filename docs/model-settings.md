# 网页模型设置

模型渠道可在页面修改。运行 `npm run serve`，打开终端打印的本机地址，点击“模型设置”（网页右上角，默认地址为 `http://127.0.0.1:8788/app.html`，也可直接打开 `http://127.0.0.1:8788/settings.html` 跳转到设置抽屉）。即使尚未配置模型和搜索服务，也能启动网页。

## 填写与保存

| 字段 | 填写内容 |
| --- | --- |
| 服务地址 | 渠道的 HTTP/HTTPS 基础地址，通常以 `/v1` 结尾，不包含 `/chat/completions`、查询参数或账号密码 |
| 模型名称 | 渠道支持的完整模型 ID，保留名称中的大小写和路径 |
| API Key | 首次填写渠道密钥；同一服务地址下留空可沿用，填写新值则更换密钥 |
| 推理档位 | 高级设置，支持服务默认、关闭、最低、低、中、高、最高；按模型族映射：DeepSeek 为 low/high/max，MiniMax 为 minimal/low/medium，其他模型按 OpenAI 兼容的 `reasoning_effort` 传所选档位。不支持推理参数的模型请选择“服务默认”，保存前可用“测试模型”确认。旧版保存的 `on` 按最高档兼容 |
| 上下文长度 | 高级设置，按渠道说明填写；默认 262144，允许 1024–2000000 的整数。请求前会按该值估算 token，保留课程计划、上一回合和当前输入，裁剪较早历史并收紧输出上限 |
| 每分钟请求数 | 高级设置，按渠道配额填写；默认 8，允许 1–600 的整数。达到本地设置的频率时排队等待 |
| 教研执行时限 | 高级设置，单位分钟，允许 1–30，默认 8；限制单个知识点一次回合的实际请求与工具执行时间，渠道等待另计 |

点击“保存设置”后会显示成功提示和保存时间。刷新或重启后仍保留配置；页面和读取接口只显示密钥是否已配置，不回显密钥，保存后输入框清空。服务地址变更（包括路径变更）时必须重新填写对应密钥，避免把旧渠道密钥发送到新地址。

保存会验证字段并写入本机文件；实际连通性、模型可用性和额度由下一次模型请求验证。课程列表、向导、课堂、大考和实践页面均有设置入口。

### 测试模型

设置抽屉底部的“测试模型”会用当前表单中的服务地址、模型、API Key、推理档位发一次最小真实请求，**不会保存配置**。留空 API Key 时，同一服务地址沿用已保存密钥；更换地址仍要求填写新密钥。测试结果会显示模型、档位、耗时和回复片段；渠道 4xx/5xx、不支持推理参数、超时都会直接显示。该请求会产生一次真实调用费用。

## 教研搜索（可选）

页面上的"搜索服务"可选择 Exa、Tavily Hikari 或自定义 MCP：选 Exa 会自动填入 `https://mcp.exa.ai/mcp`，Token 填 Exa 的 API Key（按 `x-api-key` 发送）；Tavily Hikari 填 `https://<host>/mcp` 与 `th-` 开头的访问令牌（不是官方 Tavily key）；其他服务选"自定义 MCP"，工具名需包含 `search` / `fetch` / `extract` 片段才会被教研预算放行。保存后按网页配置优先，其次服务环境变量，最后 `.env` 的 `TUTOR_MCP_SEARCH_URL` / `TUTOR_MCP_SEARCH_TOKEN`；清空网页字段即回退到环境配置。搜索与授课一样支持热更新：进行中的教研流程在下一回合使用新搜索服务，无需重开。换搜索地址时必须填写新服务的 Token（不会沿用旧令牌）；密钥保存在本机配置文件，不会回显。

搜索工具名以 `mcp__searchix__` 开头的命名空间注入；教研预算只放行搜索类（`search` 前后是分隔符，覆盖 `tavily-search`、`web_search_exa`、`web_search_advanced_exa`）与抓取类（`web_fetch`、`web_fetch_exa`、`crawling_exa`、`*_extract`）工具，其余工具（crawl/map/research、agent_run 等）不会暴露给模型。

搜索失败分两类处理：**参数不合规**（如把布尔写成字符串）会退还本次预算并允许模型改正后重试，工具不会被停用；**服务/传输失败**不占检索次数，连续两次失败才在本知识点内停用该服务，避免一次网关抖动废掉整个知识点。`web_fetch` 抓取失败仍按原样消耗抓取次数。

来源准入在地图合并前执行：搜索结果页，以及百科、问答、文库、博客平台、内容农场（百度百科/知乎/CSDN/简书/搜狐/公众号等）会被直接剔除并提示，宁可让该知识点没有来源（`verified=false`），也不把不可核对的页面写进地图。

## 生效范围与保存位置

配置优先级为：**网页保存文件 > 服务启动环境变量 > 仓库 `.env`**。网页保存不会修改 `.env`。

每个新流程启动时读取最新配置；进行中的流程也会在**下一回合**重新读取配置（每个模型请求前解析一次）：保存新设置后，当前流程的下一次请求即用新渠道，无需重启服务或重开流程。本回合已发出的请求不受影响；换模型后前缀缓存需重新建立一次。命令行 `npm run agent -- …` 的模型流程同样在每回合读取已保存配置；查看课程、复习和执行已有实践任务等零模型操作无需模型配置。

默认保存文件为 `data/model-config.json`，使用原子替换写入，权限为 `0600`（仅当前系统用户可读写）。文件包含密钥，位于已忽略的 `data/` 目录，不提交 Git。运行时模型模板只记录密钥的环境变量名称，不包含密钥值。

多个试学目录默认共用模型配置；需要独立配置时，在启动服务或 CLI 前设置 `TUTOR_MODEL_CONFIG_FILE` 指向单独的文件，建议使用绝对路径。自定义文件也应放在 Git 忽略的目录。若已保存文件损坏，服务会明确报错并停止启动模型流程；修复该文件后再试，不会自动切换到环境中的其他渠道。

联网教研使用的搜索 MCP 地址与令牌仍在环境变量或 `.env` 配置，仅联网教研加载。其他流程无需搜索配置。费用估算仍采用 `config/cost.yaml`，切换渠道或模型后应核对单价。

## 页面一直等待时

“等待模型回复”的秒数是页面等待时间，不能直接视为模型推理耗时。旧后台进程仍在运行、页面却已更新时，可能出现回复已完成但页面无法订阅输出的情况。

请求前的等待分两种：**按每分钟请求数排队**是本地控制发送频率，例如每分钟 2 次时至少间隔约 30.5 秒；**渠道临时错误后的重试等待**是收到 429 等可恢复错误后退避再试。这两种等待都不代表账户余额不足。倒计时表示下一次尝试发送请求的时间，不是内容完成时间；其他共享请求或新错误可能延长等待。连接中断或历史流程已过期时不再显示运行倒计时。

`480s` 是 tutor 设置的 **8 分钟执行预算**，不是整门课程的完成时限。一次教研回合中的实际模型请求、搜索和正文抓取共享该时限。渠道额度排队及退避等待单独计量，每回合最多累计等待 30 分钟；独立内容审查每次请求另有 240 秒执行上限。因此正常运行时，一个知识点可能超过 8 分钟，页面会显示当前进度与等待状态。

`429` 通常是可恢复的限流。教学、教研、独立审查及传输重试按同一服务地址和密钥共享队列，包括独立 `DSH_HOME` 的进程。默认每 61 秒最多 8 次并均匀发起；后台会话标题生成已关闭。429 后从至少 61 秒开始递增等待，加入少量随机余量，本地间隔最多 5 分钟，同时遵守更长的 `Retry-After`。临时服务端、网络及超时错误也使用退避恢复。每一步最多重试 8 次；成功进入下一步后重新计算，因此间歇错误不会累积成整门课程的失败次数。持续无法恢复、等待达到独立上限，或确定的认证/余额错误才暂停并保留进度。其他程序共用额度时，本机队列不能替它们限流。

队列等待不占用执行预算，取消仍可中断等待，未发起的排队请求不消耗生成预算。新配额在新流程中生效；并行流程使用不同配额时，较低配额在一个窗口内优先。共享状态保存在 `data/model-rate-limits.sqlite`，只含不可逆的渠道标识、请求时间与配额，不含密钥、提示词或回复；可用 `TUTOR_MODEL_RATE_LIMIT_FILE` 指向各进程共用的绝对路径。

教研按知识点建立独立会话、逐点审查和保存。每点最多 3 次搜索、2 次抓取、6 轮模型生成（包括内容修复）；同一步的传输重试不重复扣生成次数，仍记录实际 HTTP 请求及已报告用量。工具只在前 3 轮可用；每条工具结果最多 6000 字符、合计最多 24000 字符。失败搜索也计入预算，同一失败搜索服务在本点不反复尝试。资料太长导致单项审查超时或截断时，生成器可在剩余预算内精简后重审；原失败保留，精简稿仍须完整批准。

课程页与教研向导显示实时状态卡：已保存数量从正式课程读取，当前节点、审查和等待状态经已有 SSE 流程传输；断线时明确提示重连。倒计时不增加完成数。网页教研使用独立 Harness 目录，模型配置仍取网页保存值，无需重启服务。教研目录中的 `transport.jsonl` 只记录实际 HTTP 时间、状态与允许的响应头，便于核查恢复行为。

课程详情区分“待教研”“已保存 · 待交叉验证”“来源已验证”。默认继续会跳过已保存的完整教研结果，来源不足或尚未相互印证不会冒充已验证；两个不同域名只是数量门槛，不会自动令 `verified=true`。可点击任一知识点的“补查”单独重研。断点绑定课程范围、节点摘要与来源，相关内容修改后重新处理。已保存的节点不会因后续节点失败而丢失，连续两个节点失败后停止本次运行。

页面现在会在启动流程前检查后台协议。如果提示“后台服务与页面版本不兼容”，先结束旧服务，再在当前代码目录运行 `npm run serve` 并刷新页面。设置保存本身无需重启；只有更新后台代码时需要重启旧进程。已保存的课程状态和原始会话日志会保留，未发送的输入不属于已保存作答。
