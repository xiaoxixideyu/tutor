## 协议与兼容性

- 大考 `ExamGrading.score` 统一为 0–1；`computeExamResult(paper, gradings)` 负责乘权重。旧考试未保存可完整重算的试卷，因此不自动重算历史成绩。
- `reviewQuestions` 为每个知识点返回 `attemptId`；`submitReview` 必须原样回传它，并提交完整答案数组。最近一次回执保存在该节点的 `mastery.yaml.last_review`，与掌握度同一次原子文件写入。
- `/flow/start` 与 `/flow/state` 返回 `flowId`。`/flow/input`、`/flow/stop` 必须提供对应 ID；SSE 使用 `/flow/stream?flowId=...`。升级后已打开的旧网页需要刷新。
- 实践流程支持 `nodeId`，参与流程身份及子进程参数。不同知识点不可复用同一活动流程；网页在切换确认期间禁止向旧任务提交输入。
- 新计划保存 `scope`（完整课程范围），`path` 继续跳过规划时已掌握节点。旧计划用知识地图作为范围，保证复习降级后仍有补救课。
- 知识地图读写统一执行来源门槛；两个不同注册域名只是独立来源的保守代理，不证明机构独立或事实正确。读取旧文件不写盘，下一次写入会保存重新判定的标记。
- 服务保留最近 8 个流程的内存回放，每个最多 400 块／约 1 MiB；服务重启后课堂与摸底由原有持久化断点恢复。当前逐题就绪仍兼容终端提示符，尚未替换为完整领域事件协议。
- 网页阻止同课程的活动 runner 与复习并发写入；CLI 之间尚无跨进程文件锁。

## 下一阶段：真实模型与教学效果

选择 Go 与一个非编程领域，使用独立验收课程，不覆盖正在学习的课程。先跑通访谈、教研、摸底、规划、课堂、小测与大考；编程课程再验证实践任务。

1. 固定主观题、参考答案与人工评分，覆盖全对、部分正确、概念错误和无效判分输出，重复评估模型判分一致性。
2. 同时记录教学计划覆盖率、课堂是否完成、人工核对的事实错误。`partial=true` 时的高覆盖率只代表已讲到部分，不能代表整课完成或已经学会。
3. 用课后、隔日与一周后的独立题目衡量掌握和保留；记录补救课能否改善表现，不反复使用同一题作为学会的证据。
4. 统计教研、备课、讲授、重试、事实核对、判分的完整 token 与实际账单，之后再决定模型分级与成本预算。
5. 多来源验证、实践的操作系统级隔离、单进程宿主迁移分别验收，不随网页功能完成而默认达标。
