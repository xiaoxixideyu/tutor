# 2026-10-09 联网教研超时修复与实测

本次针对 `agent5` 的 39 节课程排查反复出现的 `480s` 超时。结论是流程设计缺陷与外部服务异常叠加：原程序放大了模型等待和搜索失败，真实模型渠道也确实出现连续路由错误。调大时限不能解决这些问题。

本机原始证据保存在 `data/evals/research-recovery-2026-10-09/`，会话位于 `data/dsh-home/sessions/`，课程内容及准入记录位于 `courses/agent5/`。运行数据不入 Git。个人 `.env`、课程档案和两份原有 audit 文件的哈希保持不变。

## 原故障

用户截图对应的教研会话为 `session-beb18e32-6ffb-4cb3-b38a-d36f6e7e5d46`，2026-10-09 11:55:41–12:03:42（上海时间）。从原始日志逐事件统计：

Exa 两次返回 `503: no exa capacity available right now`。旧设计将三个知识点放在同一会话中，搜索限制主要靠提示词，长正文不断进入上下文，整批完成后才保存；更新地图时又重新审查整张地图。超时不是浏览器计时器自行报错，也不是模型渠道规定的“思考额度”。

`480s` 是 tutor 为一次教研回合设置的预算，覆盖其中的模型与工具调用。独立内容审查每个请求另有 240 秒上限，因此整个知识点或课程的总等待可能超过 8 分钟。

## 修复后的行为

- 按单个知识点建立独立会话、核查、保存；后续失败保留先前结果，连续两点失败后停止继续消耗。
- 每点硬性限制为 3 次搜索、2 次正文抓取、5 次模型请求，重试和修复不重置计数；仅前 3 次请求可用工具。每条工具结果最多 6000 字符、合计最多 24000 字符，同点失败的搜索服务不反复尝试。
- 资料摘要更短，保持骨架标题，不因标题同义改写要求模型重新生成；避免无关的章节编号与冗长方法清单。
- 地图仅为变化内容发起新检查。未变化检查必须逐字匹配请求、重新解析，并保有完整有效的原始证据；最终批准仍覆盖全部单元和断言。
- 资料分批审查带上完整课程节点与当前资料归属，避免把不含 `outline` 的片段误解为“课程地图为空”。旧含来源地图的准入摘要因此变化，不能继续借用缺少该上下文的批准。
- 单项资料审查超时或截断时，可在剩余生成预算内精简后重审；原稿及失败保留。网络、认证或审查格式错误仍停止本次发布，未完成检查不能变成批准。
- `research-progress/` 单独记录已完成的调度断点。已保存但来源不足的节点保持 `verified=false`，默认继续不重复处理；按节点补查可重新研究。节点资料或课程范围变化会使相关断点失效。
- 课程详情显示已保存与来源验证数量，提供单点教研、补查和继续剩余入口。重试保留指定节点，完成单点不再声称整门课教研完成。
- 页面高级设置可调整教研回合时限，范围 1–30 分钟，默认 8；只影响新启动流程。提高该值不提高模型速度，也不改变独立审查的 240 秒限制。

## 真实运行中发现的问题与恢复

本轮没有把“减少搜索”当成修复完成，继续运行后又暴露了标题过度校验、资料版本编号矛盾、审查缺少节点上下文、输出截断及渠道路由错误。

1. 首次单点生成已得到完整 JSON，但严格比较标题导致额外生成并耗尽请求预算。改为保留骨架标题后，从真实会话的最后完整 JSON 恢复为待审候选；恢复记录在 `recovered-candidate.json`，没有手工签发批准或发布内容。
2. 候选的 `list.pop()` 返回值和文档章节号被拦截。修复与再次审查又遇到 240 秒超时和 8192 token 截断，原记录均保留。这次候选没有保存为正式资料。
3. 使用较短摘要重新运行时，资料审查把空的局部上下文误认为完整空地图，错误拒绝来源；该旧审查修复流程被主动中止，待审记录保留。随后补齐资料所属课程节点。
4. 新审查正确拦截了“`__exit__` 只有返回 `True` 才抑制异常”的错误表述：实际应按返回值的真值判断。自动修正后，审查被连续两次 `404 Route Not Found / bad_response_status_code` 中断。这是模型渠道返回的真实错误，不是仅凭等待时长推断。
5. 恢复同一待审草稿时复用 21 项检查，只补 1 项，约 71.2 秒完成该次审查，没有重新生成或搜索。`python-core-refresh` 正式保存并通过来源验证，3 条来源；完整地图准入有效。证据为 `first-node-saved.json` 和 `first-node-after-channel-error-events.jsonl`。
6. 从课程页面启动 `python-packaging-env`。本轮同样受 3 次搜索、2 次抓取上限约束；审查再次遇到输出截断和连续路由 404。故障后核对第一点正文、三条来源和准入均未变化，证据为 `second-node-failed-progress-preserved.json`；随后通过页面“重试本知识点”恢复。

这些尝试不能合并成“一次成功”，也不能只计算最后恢复的费用。完整失败及已报告用量保留在原会话、审查记录与 `review-timings.json` 中；缺少用量的失败不能解释为零计费。
