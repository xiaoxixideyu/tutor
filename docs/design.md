# 项目设计文档：导师（tutor）——个性化教学 agent

> 创建日期：2026-09-02
> 状态（2026-10-08）：教学主链路与三期功能已实现，正在修正可靠性并建立教学效果基线。本文保留原设计与历史验收记录，当前验证范围见 [regression.md](regression.md)。
> 定位：本仓库即 tutor 项目仓库。基于 DeepSeek Harness 基座，融合 Reasonix 的工程优点。
> 相关资料：agent 学习笔记与概念沉淀在 [learn_agent 仓库](https://github.com/xiaoxixideyu/learn_agent)。

## 1. 愿景与北极星

**一句话**：一个能替用户定制并执行完整教学闭环的教学 agent——从需求澄清、教研、摸底、规划，到讲授、检验、复习，全程因材施教。

**北极星**（所有设计决策都要被它证明）：

> **教学有效，且便宜到用户敢天天用。**

三条设计原则：

1. 每个设计都能被北极星解释（学 Reasonix：有主见，不通用）。
2. 课程状态持久化，随时中断、随时继续（学 Harness：日志是唯一事实来源）。
3. 成本内控、分级调度（成本在内部台账按模型核算，不向学员展示）。

## 2. 已拍板的关键决策

| 决策项 | 结论 | 理由 |
|---|---|---|
| 交互形态 | 命令行 | 第一版先跑通闭环，不背界面包袱 |
| 用户规模 | 单用户 | 先自用，闭环成立再谈产品化 |
| 模型接入 | 仅 OpenAI 兼容接口 | 配置 base_url + api_key + model 即可；DeepSeek 即兼容该协议，且此类服务商普遍自带**前缀缓存**（prefix cache） |

## 3. 教学闭环：七个环节

| # | 环节 | 做什么 | 输入 → 输出 | 期数 |
|---|---|---|---|---|
| 0 | 需求澄清 | 访谈：目的、时限、每日投入、现有基础、讲解偏好 | 用户陈述 → 课程档案 | 一期 |
| 1 | 教研 | 产出知识地图：大纲 + 知识点依赖 + 优质资料 + 来源 | 领域 → 知识地图 | 二期（一期用模型自带知识，标注"未联网验证"） |
| 2 | 能力测评 | 自适应摸底：答对加深、答错收窄 | 小测作答 → 能力画像 | 一期（题库内置） |
| 3 | 课程规划 | 知识地图 × 能力画像 → 个性化路径 + 里程碑；计划随进度修订 | 两份画像 → 教学计划 | 一期 |
| 4 | 教学执行 | 备课 → 对话式讲授 → 课中练习 → 现场调整（换讲法） | 本课计划 + 资料 → 掌握信号 | 一期 |
| 5 | 质量校验 | 三层：课中反问 / 单元小测 / 里程碑大考 + 实践任务 | 作答 → 判分 → 掌握度更新 | 一期（实践任务沙箱执行二期） |
| 6 | 复习巩固 | 间隔重复对抗遗忘；回访先复习再继续 | 到期清单 → 复习课 | 一期（简化算法） |

补充的环节 0 和 6 是原需求缺失的关键：**没有 0 就没有真正的"定制"，没有 6 就没有真正的"学会"**。

## 4. 核心架构

### 4.1 三个关键判断（落地方式）

**判断一：课程 ≠ 会话——课程是持久化的结构化状态**

```
课程状态（持久化，活几周）
  = 课程档案 + 知识地图 + 能力画像 + 教学计划 + 掌握度记录 + 资料库

每节课的上下文（新建，小而精）
  = 课程档案摘要 + 本课计划 + 本课资料 + 最近掌握度
  （绝不塞入几周的历史对话）
```

这是上下文工程的核心应用：**记忆无限、上下文有限**。课程状态存文件，是"记忆"；课堂上下文每课重建，是"注意力"。

**判断二：显式工作流 + 内嵌 agent**

七个环节是明确可枚举的 → 用**工作流（workflow）**做骨架；"讲授"是开放对话 → 环节内跑 **agent 循环**。工作流管骨架，agent 管血肉。

**判断三：成本分级**

| 活 | 频率 | 模型档位 |
|---|---|---|
| 教研（建知识地图） | 低频 | 最强档 |
| 备课、规划 | 中频 | 便宜档 |
| 讲授 | 高频 | 便宜档默认，模型可自报升级 |
| 判分 | 高频 | 客观题规则判分（零成本）；主观题判分模型 |

### 4.2 教学执行的单课循环（工作流细节）

```
备课 → 讲授（agent 循环）→ 单元小测 → 判分 → 更新掌握度 → 推进计划指针
       ↑                                              │
       └──── 掌握度差 → 插入补救课 ←──────────────────┘
```

备课产物（讲解结构、例子、练习题、小测题）属于**易变草稿**——只在当课用，不进长期记忆。

### 4.3 核心与壳分离（架构纪律）

**纪律**：所有能力都做成**无头核心（headless core）+ 薄壳**——教学闭环、课程状态、判分全部在核心里；命令行只是第一个薄壳，对核心零依赖假设。

为什么：

1. 教学闭环一定会随真实使用迭代，改逻辑在命令行壳里成本最低；若逻辑和界面耦合，每次迭代都是前端返工。
2. UI 是大投入（聊天流、测验表单、进度看板），在核心验证前不投。
3. 未来上 UI 的路径现成：核心挂 Harness 的 SDK 档案（对外暴露 JSON-RPC 服务）→ 前端接上（可用 Harness 自带网页应用捆绑包起步，或自建前端）。

验收锚点：**删掉命令行壳，核心能力依然可被任何新壳直接调用。**

## 5. 数据模型（课程状态）

```
tutor/
  courses/
    <course-id>/
      profile.yaml        # 课程档案
      knowledge-map.yaml  # 知识地图（含来源）
      learner-profile.yaml# 能力画像
      plan.yaml           # 教学计划（路径 + 里程碑 + 当前指针）
      mastery.yaml        # 掌握度记录（逐知识点 + 复习到期日）
      materials/          # 资料库（缓存正文 + 来源元数据）
      sessions/           # 每节课的会话日志（交给基座管理）
```

关键 schema 示例（节选）：

```yaml
# profile.yaml
goal: 掌握 Go 后端开发，能独立完成 Web 服务
deadline: 2026-12-31
daily_minutes: 60
background: 有 5 年 Java 后端经验
style: 例子驱动，先动手后理论

# plan.yaml（节选）
path: [interfaces, goroutines, channels, context, testing]
milestones:
  - id: m1
    title: 能写出并发安全的 worker pool
    nodes: [goroutines, channels]
current: goroutines

# mastery.yaml（节选）
goroutines:
  status: learning        # mastered / learning / weak / unknown
  score: 0.6
  review_due: 2026-09-09  # 间隔复习：1/3/7/14 天简化算法
```

设计取向：**第一期课程状态直接用文件**（简单、可读、可手改）；文件变更同时写入会话日志（事件），满足"模型可见即已记录"。不为第一期引入完整事件溯源 machinery。

## 6. 技术选型与结合方式

### 6.1 基座：DeepSeek Harness

采用它的四个能力：

1. **一切皆插件**：模型适配、工具注册、会话日志、agent 循环全部可替换。
2. **会话日志 = 唯一事实来源**：课堂对话、工具调用全部入日志；恢复、回放、审计免费获得。
3. **能力接缝**：文件系统、子进程、沙箱、子代理都是可替换实现（第二期实践任务直接用沙箱接缝跑测试）。
4. **配置档案组装**：教学 agent 的各种形态（如"纯备课模式""快问快答模式"）用不同配置档案组合出来。

### 6.2 Reasonix 优点 → 自定义循环插件

Harness 明确允许替换 agent 循环，因此把 Reasonix 的三根支柱实现为一个**循环插件**：

| Reasonix 支柱 | 在本项目的实现 |
|---|---|
| 缓存优先循环 | 三区上下文：不可变前缀（教学人格 + 方法论 + 工具清单）/ 只增日志（课堂对话）/ 易变草稿（备课草稿，不上传） |
| 工具调用修复 | 展平、捡漏、截断修复、防风暴四道工序 |
| 成本控制 | 便宜档默认、辅助调用一律便宜、回合末压缩工具结果（超阈值缩成摘要）、自报升级（用户可见）、内部成本台账（不向学员展示） |

前缀缓存的可用性由 OpenAI 兼容服务商保证（已拍板），循环只需保证**字节级前缀稳定**。

### 6.3 模型接入

统一走 OpenAI 兼容协议：`base_url` + `api_key` + `model` 三个配置。不绑定任何一家。分级通过配置两个模型名实现（便宜档 / 最强档）。

### 6.4 命令行设计

命令行只是第一个薄壳（见 4.3 架构纪律）：它调用无头核心，自身不承载业务逻辑。

```
tutor new <课程名>      # 需求澄清访谈 → 生成课程档案
tutor assess <课程名>   # 摸底测评 → 能力画像
tutor plan <课程名>     # 生成/更新教学计划
tutor learn <课程名>    # 开始/继续本节课（备课→讲授→小测）
tutor review <课程名>   # 复习到期知识点
tutor status <课程名>   # 进度看板（知识点掌握状态）
tutor list              # 课程列表
```

## 7. 分期与里程碑

### 第一期：单课程闭环（当前目标）

任务分解：

1. 环境搭建：Node 环境接入 Harness，锁版本（它处于开发预览期，有破坏性变更风险）
2. 最小循环：跑通一个基于 Harness 的最小 agent 循环
3. 课程状态插件：文件存储 + 各 schema 定义
4. 需求澄清访谈（结构化输出采集）
5. 摸底测评：内置题库 → 作答 → 规则/判分模型判分 → 能力画像
6. 教学计划生成（含依赖排序）
7. 讲授循环：缓存优先循环插件 + 便宜档默认
8. 单元小测 + 掌握度更新
9. 断点续学：重启后从进度指针继续
10. 成本内控：内部按模型估算开销，不向学员展示

**第一期验收标准**（2026-09 全部通过）：

- [x] 能创建"golang"课程并完成需求访谈，产出课程档案
- [x] 摸底测评能真实区分"有基础"和"零基础"两种画像
- [x] 计划能跳过已掌握知识点、按依赖排序
- [x] 能对话式讲授一节课，含课中练习和现场换讲法
- [x] 课后小测判分正确，掌握度被更新
- [x] 重启进程后能从断点继续，上下文不膨胀
- [x] 成本内部可核算（按模型估算，界面与终端不展示开销）
- [x] 核心不依赖命令行——删掉命令行壳，核心能力仍可被任何新壳直接调用

### 第二期：教研系统
网搜 + 多来源交叉验证 + 知识地图生成 + 资料库 + 引用（讲授中的事实断言须可溯源）。

### 第三期：多课程 + 强化复习 + 前端壳
多课程并行管理、完整间隔重复、实践任务沙箱执行（写代码跑测试）；挂 SDK 档案把核心暴露为 JSON-RPC 服务，接前端 UI（可用 Harness 自带网页应用捆绑包起步）。UI 的核心价值（进度看板、课程列表、结构化测验）恰好在多课程阶段才真正需要，时机正好。

> 进展（2026-09-19）：多课程体验（review --all、跨课程到期汇总、到期徽章、题库缺失顺延）、强化复习（SM-2 简化版：答错回退一级不清队列）、前端壳一期（核心层 JSON-RPC 方法表 + 本地 HTTP 服务 + 静态看板）已落地。Harness 的 sdk/web 档案经调研暂无可插领域方法面（SDK JSON-RPC 仅 stdio 且仅会话驱动方法），档案挂载待其演进。
>
> 进展（2026-09-20）：**实践任务沙箱落地**——practice-gen（模型出题：每知识点 1 个动手任务 + 1-3 条规则化测试）+ practice（零模型交互壳：学员在 courses/<id>/sandbox/<task_id>/ 写代码、回车跑测试、规则判分；全过则掌握度保底 0.8 且复习阶梯不越权推进；断点续做：workdir 持久化 + starter 文件不覆盖学员改动 + practice-state 落盘）。执行器本期为受控子进程直跑（超时/输出上限/GOPROXY=off），接口与 Harness ctx.shell 对齐可平滑切换。
>
> 进展（2026-09-20）：**里程碑大考落地**——exam 命令（自动选下一个可考里程碑：节点全 mastered 且未通过过）。客观题规则判分（零成本），主观题判分模型（score 0-1 部分给分 + note 依据）。通过 ≥0.7 记里程碑达成；未过回退指针到薄弱节点（补救课语义）。试卷质量实测：陷阱题/语义辨析/综合验收题分层清晰。三期全部任务完成。
>
> **架构决策留痕（2026-09-20）——进程形态与 UI 归属**：
>
> 1. **单进程 = 目标形态，当前被基座卡住（2026-10-15 已通过去 dsh 重构解决，见下方决定）。** dsh 本身是单进程 Cordis 插件树；我们的 serve↔headless 子进程桥接是过渡态妥协。官方 web 档案（单进程宿主）无法挂第三方业务方法（无可插领域方法面）且页面不可替换；sdk 档案仅 stdio 会话驱动方法。自建宿主（拼装 dsh 内部包）= 逆向官方组合规则，违反"锁版本"红线，不做。
> 2. **UI 即插件 = 终局形态，迁移有触发条件。** Harness 的 client UI 全部是插件（ConversationNodeDefinition + keyed renderer，注册进 ctx.uiConversation），完全官方的路是写 client 插件挂进官方 web 宿主。暂不迁移：①须按官方 shell 框架重写现有约 700 行自设计页面；②client 侧插件对 npm 安装版宿主的注入机制未验证，且 client API 是 breaking 风险最高的层。**迁移触发条件：基座升级评估确认 client 插件注入可行 + 真实使用证明需要官方框架能力（多会话并行/图片附件）。**
> 3. **桥接层的教训已固化**：输出回放缓冲（断线重连不丢历史）、子进程退出前断 stdin（dsh 树等管道 EOF 挂起）、stdin 监听前置（生成期早到输入不丢）。这些 bug 面随单进程收敛整体消失。
> 4. **升级评估结果（2026-09-20，rc.1 → rc.2）**：rc.2 接口面零破坏（tsc/127 测试/e2e 全绿），已合入锁版本。0.1.6-alpha.1 为坏版本（bin 引用未发布的 app-boot 导出，启动即炸）拒绝。rc.2 的 sdk-app 仍未开放自定义方法注册与 client 插件注入——单进程收敛与 UI-as-plugin 继续等待基座演进，下次触发点：0.1.6 进入 rc 或 client 注入面有官方文档。

### 第四期：打磨
对 agent 本身的评测（判分一致性回归、教学忠实度抽查）、成本看板、多领域内容质量打磨。

> 进展（2026-10-08）：修正大考评分尺度（0–1 比例统一乘题目权重）、同知识点多题先汇总再一次更新、模型判分异常有界重试；复习提交绑定题目与状态版本，回执与掌握度原子落盘；课程阶段优先识别未完成摸底；网页流程具有独立 ID，输入／停止／SSE 按流程隔离，退出后的结果可回放，超时停止结束整个进程组。Node 24 下 168 个无模型测试通过，另完成隔离数据与模拟 runner 的浏览器检查。尚未重新执行真实模型全课程验收。
>
> 当前与原设计的差距：默认仍为单模型；完整自定义缓存循环与工具修复未落地；课程状态依赖 YAML，尚无状态事件回放；资料验证已增加两个不同注册域名的硬性门槛，但机构独立性与内容相互印证仍需核对；实践尚为本机子进程；教学效果与完整成本仍需要真实使用验证。下一阶段按 [回归与评测清单](regression.md) 推进。

> 稳定性收尾（2026-10-08）：`plan.scope` 保存完整课程范围，`path` 仍表示规划时的待学节点，旧计划借助知识地图恢复范围。实践的选点与生成不再排除 mastered，网页按节点隔离流程；资料验证在读写时统一执行，重新教研替换本批旧资料、按重定向最终地址计数。187 项测试及隔离浏览器验收通过，见 [验收记录](stabilization-2026-10-08.md)。历史“三期全部任务完成”只表示主功能已落地，不包含尚未完成的隔离、基座迁移和教学效果验收。

> **架构重构（2026-10-15）——去 dsh，落地单进程（功能结果导向）**：
> 1. **形态**：`npm run agent -- serve` 是唯一进程；每条教学流程在进程内作为 async 任务运行（输入=内存队列，停止=信号中止 + 超时释放），SSE 协议与页面回放不变。原先的 serve↔headless dsh 子进程桥接、`src/plugin/` 的 Cordis 插件化、`config/settings.yaml|cordis.patch.yml|search.patch.yml` 的运行时渲染全部删除。
> 2. **新增**：`src/runtime/`（OpenAI 兼容流式客户端、工具循环、会话日志、限流/退避/看门狗——可靠性逻辑从 core 原样平移）；`src/flows/`（八个教学流程 + 内容审查网改为普通函数编排）。`src/core/` 与页面、课程状态格式保持不变。
> 3. **兼容**：会话日志仍写多帧 zstd JSONL 且沿用原事件名（`user/message`、`assistant/message`、`assistant/attempt`、`turn/end`），`audit`/`fidelity` 零改动；`messages.jsonl` 保存完整消息转录，支撑课堂断点恢复。
> 4. **依赖**：移除 `@deepseek-ai/dsh`（连带 410 个传递包）；教研搜索改用官方 `@modelcontextprotocol/sdk`（streamable-http，实测 searchix 检索与交叉验证可用）。

> **教研长度校验反馈修复（2026-10-20，第二轮 kafka2 失败复盘）**：模型输出超长（summary 167/120、material 299/180）时，校验错误只报"超过 N 字"且一次只报一个字段，模型每轮只肯微缩十几字、修一个字段，3 轮修复耗尽每节点预算仍超限而失败。现改为：一次报全部超限字段并给出当前字数与需删字数，附明确压缩策略（删举例/修饰/重复，不新增内容）；提示词加入逐字段自检与"超限会被拒绝并浪费重试预算"；每节点模型请求预算 5 → 6，为修复留出一个完整重试位。356 项测试与类型检查通过。
