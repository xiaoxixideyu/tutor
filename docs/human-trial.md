# 真人试学操作手册

目的：确认学习者能否独立使用完整流程，以及课程之后能否解答新的同范围问题。工程模拟作答、准入回执和系统的 mastered 状态都不作为真人学会的证据。

## 首轮安排

先邀请两名自愿参加者，每人只试一个主题。Go 参加者应会变量、循环、函数及基本代码阅读；概率参加者应会整数、分数与简单集合列举。用 `p01`、`p02` 等代号记录，不填写姓名或联系方式。首次由观察者在旁记录问题，预计预留 60–90 分钟；两节各 15 分钟是内容目标，模型等待另行计时。

试学前阅读[最新工程验收报告](readiness-2026-10-08.md)，确认适用范围和已知限制。两门微课的工程验收已完成，首轮仍由观察者陪同；若模型通道持续报错或课程无法继续，先记录并恢复服务，不让参加者承担排错工作。

## 启动与恢复

使用 Node 24，在仓库中配置好 `.env` 后运行：

```sh
npm install
npm run trial -- --learner p01
```

打开终端打印的本机地址。首次应显示空课程列表；按“开设新课程”完成访谈、摸底、计划和两节课。资料存入 `data/trials/p01/`，课程、工作目录、会话与审计均按人隔离。重复同一条命令继续原进度；下位参加者使用不同代号。不要复制 `data/evals/` 或开发课程到试学目录。

若端口已占用，可用 `TUTOR_SERVER_PORT=8789 npm run trial -- --learner p01`。结束服务按 Ctrl-C。服务只监听本机，当前适用于一台电脑上的单用户流程。

访谈时由参加者说明实际基础与困难。观察者只提供以下范围约束，不代替参加者回答摸底或课堂题：

- Go：严格两节各 15 分钟，第一节学习 `[]int` 赋值、切片表达式与共享底层数组，第二节学习 `make + copy` 创建独立副本和修改验证；排除 `append`、扩容、并发和嵌套切片。
- 概率：严格两节各 15 分钟，只学习一次掷一枚公平六面骰子的样本空间、有利结果计数及补集公式；排除多次试验、条件概率、独立性、统计推断和编程。

联网教研可选。未完成来源核实就保持“未验证”，不把这个标记改成已验证。断网或审查失败时，从保存的进度重试；等待也要记入记录。

大考已提交的答案逐题保存。输入 `/exit` 或点击“暂停大考”后，用“继续考试”恢复；已回答的题目会跳过，成绩页刷新会显示同一场结果。尚未发送的输入不算已提交答案。

## 每人执行顺序

1. 开课前完成相应题册的“前测”，限 8 分钟。不会可以空白；观察者暂不反馈答案。
2. 完成两节课程。自然提问和犯错都保留。至少实际使用一次暂停续学、内容核对、小测、实践和里程碑考试；观察者记录是否需要代操作。
3. 课程结束后立即做“课后测”，限 8 分钟，不查课文、不用模型提示。模型和系统成绩不能替代独立评分。
4. 约 24 小时后做“次日测”，约 7 天后做“一周测”。记录实际间隔，不修改系统日期冒充跨日测量。为区分保留和复习效果，先做独立测试，再使用系统到期复习；期间自发复习也如实记录。
5. 观察者按评分说明记录逐题得分、原始作答、等待、求助、报错和费用。最后询问“哪里最难懂”“哪个步骤最想退出”“还有什么不能独立完成”，保存原话。

题册：[Go](trial-go-forms.md)、[概率](trial-probability-forms.md)。每次只向参加者提供当前时间点的一组题，后续题目和[评分说明](trial-evaluator.md)由观察者保管，不粘贴进导师对话。原始记录使用 [CSV 模板](trial-record.csv)，每次测量一行，作答正文另存同一试学目录。

## 实践与数据

当前实践测试会在本机启动命令。观察者先阅读任务的命令和初始文件，使用专门试学工作目录。程序会过滤服务密钥、限制时间与输出、阻止不安全初始文件路径并保留学员修改，但尚无操作系统级文件或网络沙箱。首轮宜使用不含私人资料的测试账号或电脑。

课堂输入会发给已配置的模型服务；不要录入敏感个人信息。日志可能包含完整作答，保存在本地，默认不提交 Git、不公开发布。真人日志的分享与保存期限由实际组织者和参加者另行约定。

费用按配置单价估算，记录失败和重试；搜索费用及未报告用量另列，实际账单未核实时留空。不要将模型推理首块时间写成页面首字时间。

## 如何决定后续工作

- 出现错误事实、超出明确范围的任务、错误答案被稳定判对或学习记录丢失：先记录原题与操作，暂停扩大试学，修复后重新工程验收。
- 流程可以独立完成，但等待或求助过多：优先改进失败恢复、反馈和交互，保留原始等待数据。
- 逐题报告前后及跨日成绩，同时报告是否完成、提示次数和额外复习；同义但正确的答案按同一规则给分。可将每次至少 6/8 分且关键概念未错作为探索性目标，不能凭两名参加者声称学习效果得到统计验证。

真人参加者的招募、实际作答、跨日回访和主观反馈需要人来完成；工程脚本不代做这些步骤。
