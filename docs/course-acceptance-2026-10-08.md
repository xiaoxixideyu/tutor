# 2026-10-08 真实模型微课程验收

本轮结论：教学流程和状态迁移可以运行，但生成内容尚未通过质量验收。概率期末卷仍明显超出课程范围，Go 资料与讲授有错误概括，资料对照未能可靠识别这些错误。不能把考试通过或知识点显示为 mastered 当作课程准确、学员学会的证据。

项目的目的，是让一个教学 agent 根据学员目标和基础，完成访谈、教研、摸底、规划、讲授、练习、考试及间隔复习。本轮使用正式运行器和独立课程目录，对这条业务链做真实模型验收；学员由代码助手模拟，不涉及真人学习效果。

## 验收范围与结果

两门课程都限定为两节各 15 分钟微课。Go 只讲 `[]int` 共享底层数组和 `make + copy` 独立复制；概率只讲一枚公平六面骰子一次试验的样本空间、计数和补集，排除独立性等后续主题。固定条件见 [course-acceptance.json](../evals/course-acceptance.json)。

| 环节 | Go 切片 | 基础概率 |
|---|---|---|
| 访谈与教研 | 档案保存；重生成后地图为 2 节、4 条来源 | 档案保存；重生成后地图为 2 节、6 条来源 |
| 摸底与规划 | 用典型误解作答，两节点薄弱；生成两个里程碑 | 用典型误解作答，两节点薄弱；生成两个里程碑 |
| 两节课堂与小测 | 两次小测均 3/3，按顺序推进并完成 | 两次小测均 3/3，按顺序推进并完成 |
| 里程碑考试 | m1 得分 0.97，m2 得分 1；m1 存在不合理扣分 | 两场均得分 1；m1 参考答案有错，m2 范围不合格 |
| 实践 | 两个任务的未完成版本失败、正确实现通过、典型错误被拒绝 | 两个文本作答任务完成同样的正反验证 |
| 到期复习 | 两节点答对，复习日期推进 | 第一节点故意答错后降级，第二节点答对后保持掌握 |

四个实践任务都经正式 CLI 执行并写入状态。Go 独立复制任务包含学员测试和生成的评分测试；另外独立编译、执行了期末提交的 Go 测试代码。重入实践保留学员文件。第一项 Go 任务主要检查 stdout，无法防止硬编码；概率任务对文件名、集合顺序与分数格式较敏感，不能外推为开放作答评测能力。

复习日期只在独立测试课程内提前到当天，保留修改前后记录；这不是隔日或一周后的真实记忆测量。概率第一节点降级后，看板与课堂都回到该节点；补救讲授针对重复计数和边界条件，小测 3/3 后恢复已掌握，再次开课没有调用模型并确认无待学知识点。最终状态见本地 `review-date-simulation.json`。

## 已修正的工程问题

- 教研与摸底原来的固定节点数量要求，把两节微课扩成 17 和 15 个节点。改为服从明确课时及范围，重跑后均得到两个节点。
- 摸底题库改为逐节点生成、完成即保存，避免一次生成整库耗尽输出预算。实测中断后保留已完成节点，只补缺失题目；已有完整题库时不再调用模型出题。
- 主动取消模型回合不再触发自动重试，已消耗用量仍计入。新增自动化回归，并在真实中断中复核。
- 统一选择题标号，避免 `A. A.` 重复及复习选项无标号。
- 修正完成课程的 CLI 看板文案，不再把没有待学节点显示成“未开始”。
- 实践允许非编程学员提交文本答案。实践和考试提示接收课程范围与排除项，考试区分整门课程目标和当前里程碑；这些提示改善了部分输出，尚未构成可靠约束。
- 阅卷以题干要求为评分边界，不能因遗漏参考答案的额外细节扣分；独立核对参考答案，对正确纠错的作答给分。
- `/check` 的结果改称资料对照，取消“讲授中请以此为准”的表述，说明其不能替代独立事实验证。
- 增加真实课程验收入口、阶段日志、失败与中断记录、源码哈希、延迟和费用汇总。用法见 [course-acceptance.md](course-acceptance.md)。

当前网关曾把普通问候词“你好”误判为敏感内容：对照请求与备用路由错误信息相互印证。访谈和课堂改为直接进入主题后，访谈可以继续；网关限制本身尚未修复，不能保证所有普通输入均可用。

## 内容验收未通过的证据

1. **错误参考答案。** 概率 m1 中 A={1,2}、B={2,4,6}、C={3,5}，参考答案将概率和写成 1。实际是 7/6，因为结果 2 被重复计数。独立作答指出后，阅卷模型正确承认参考有误并给满分；原卷保留。
2. **题干外扣分。** Go m1 的程序、输出和解释满足题干，却因未补充参考答案中的 len/cap 细节被扣分。修正后保存原题和原答案为固定回归样本，未改写原考试成绩。
3. **范围约束仍不可靠。** 概率实践初稿引入两枚骰子，重生成后改成单骰子纸笔题；但期末卷在新提示下仍有 4/6 题涉及双骰子、转盘、重复投掷或密码。Go m1 也出现了下一节的独立复制题。完成这些题仅用于验证系统流程，不代表范围验收通过。
4. **错误资料传播。** Go 资料和第二节讲授将“目标长度至少等于源长度”误说成“必须等长”，又将 `%p` 地址不同泛化为底层数组独立的证据。教师在较长目标、偏移切片反例的追问后纠正了说法。独立执行 Go 代码验证了这些反例。
5. **资料对照不等于事实验证。** `/check` 同时支持了“必须等长”和“至少源长度即可完整复制”，并继续支持错误的地址推论。来源来自不同域名、模型给出 supported，都不足以保证结论正确。恢复课堂后的对照也只覆盖当前进程收集的发言及上次最后回复，不能冒充完整历史审计。
6. **题目存在重复与范围漂移。** 概率课堂曾把小测的“不可能掷出 7”提前用作练习，Go 小测的零值题也在课堂出现；概率课堂在学员再次提醒后仍引用多人午餐例子，第一项实践的 README 有范围外的可选活动。小测满分只能证明该次规则判分与状态推进。

原始教材、试卷、错误尝试和被拒绝的实践稿均保留，没有通过手改答案来制造验收通过。

## 阅卷修正的复测

[course-grading-regressions.json](../evals/course-grading-regressions.json) 保存上述两个真实阅卷错例的原题、参考答案及独立作答，每例在独立会话中重测三轮，6/6 次均得应有的满分。原有 12 个固定样本又测两轮，24/24 次落在预期区间，包含部分正确、概念错误和夹带改分指令的答案。

这些期望由代码助手按题干确定，尚未经真人盲评；有限样本通过不能证明所有开放论述或代码题均能稳定判分。

## 模型、成本与证据口径

本轮前段使用 `deepseek-v4.1-flash`，后段以进程环境临时覆盖为 `deepseek-v4-pro`。未改变项目 `.env`。这些名称是网关路由标识，不能据此确认底层模型身份；不同阶段的混合运行也不是公平的模型速度对比。

两个路由都出现过输出预算耗尽。曾尝试关闭推理，虽然获得正文，但样例参考答案出错，因此没有采用这项配置。单个阶段的八分钟上限包含等待作答与人工检查，若因此退出仍记录为失败；阶段墙钟时间不能直接代表模型延迟或学员真实课时。

## 接下来应优先做什么

1. **增加内容进入课堂前的审查。** 将学员范围及排除项保存为可核验约束，分别审查知识地图、备课、练习和试卷；超纲时拒绝使用并保留修订记录。只调整提示不能视为完成。
2. **把资料对照和独立正确性检查分开。** 对可执行代码、算术及集合计数使用确定性验证；对其他事实检查原始来源与适用条件，避免错误摘要互相印证。
3. **建立独立题目与真人评测。** 先解决上述内容问题，再让少量真人完成课后、隔日和一周后的独立测试，验证补救是否改善表现。当前无需用户接手工程排查；真人学习效果需要实际学员参与。
4. **再做模型分级与运行隔离。** 用同一固定任务比较路由的可靠性、延迟与账单；实践执行仍是本机子进程，正式面向不可信作业前需要操作系统级隔离。
